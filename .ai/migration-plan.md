# WDIO → Playwright Migration Plan

Anchor for agent sessions working on the migration on branch
`feature/EB-201-convert-wdio-to-playwright`. Update the status column as steps land.

## Working agreement

- One step at a time; stop after each step with a brief (**What we have done** / **What is next**).
- Each step ends in one commit. Bulk moves get their own commit.
- WDIO / BrowserStack / Allure are removed only in step 8, after Playwright is proven.
- `playwright-migration-prompt-batteries.md` is a local working file — **never commit it**.

## Context discovered

- Frontends (reg / submit / obligations): Node + Hapi, port 3000 by default, scaffold routes only (home, about, auth, health, example). Home page title and heading: `Home`.
- Backends (reg / submit / obligations): .NET 10, port 8085 by default, MongoDB + floci, JWT via Defra ID stub.
- Template's `journey-tests.yml` wrongly calls `DEFRA/cdp-node-journey-test-suite-template/run-journey-tests@main` — fixed in step 6.
- Registration home page title is `Home | waste-batteries-reg-frontend` (`<pageTitle> | <serviceName>`). The CDP Defra ID stub serves `Home | cdp-defra-id-stub`, so the smoke spec asserts the full title to prove it hit the right service.
- The template WDIO spec asserted title `Home` exactly and had always failed against this frontend; it was deleted in step 8.
- Running the registration frontend locally: `docker compose up -d --wait cdp-defra-id-stub redis` then `npm run dev` in `../waste-batteries-reg-frontend`.
- The six service images on DockerHub are linux/amd64 only. On Apple silicon with Rancher Desktop's Rosetta emulation off, the .NET backends run under QEMU and return HTTP 500 on `/health` (NullReferenceException in endpoint metadata). Natively built images (`npm run stack:up:build`) are healthy. GitHub runners are amd64, so CI is unaffected.
- `compose.build.yml` tags built images `:local`; set `<SERVICE>_TAG=local` to mix built and pulled services (used by Depends-On in step 6).
- Browser sign-in against the stub is not wired yet: services reach it as `cdp-defra-id-stub:3200`; the first login journey must map that to `localhost:3200` for the browser.
- Step 8 removed WDIO, BrowserStack and Allure; scripts are now `test:local`, `test:local:debug`, `test:github`, `test:e2e`, `test:report` (`npm test` → `test:e2e`). `globals` became an explicit dev dependency (it was only installed transitively via WDIO). `eslint-plugin-playwright` lints `tests/`.
- Portal image: `entrypoint.sh` runs `npx playwright test` with `RUN_MODE` defaulting to `e2e`; the exit code replaces the WDIO `FAILED` marker file. A `PROFILE` that matches no tests fails the run on purpose. Under QEMU (amd64 image on Apple silicon without Rosetta) Chromium crashes, so prove the image locally with a native build (`docker build -t batteries-journey-tests:local-arm64 .`).
- CI: `journey-tests.yml` resolves service branches with `.github/scripts/resolve-service-branches.js` (Depends-On in PR body > `*-branch` input > DockerHub `*-tag`, default `latest` built from main). Branches are checked out to `services/<repo>`, built via `compose.build.yml` as `:local`, then the root `action.yml` runs the stack and tests. `run-journey-tests/action.yml` is a shim to the root action.
